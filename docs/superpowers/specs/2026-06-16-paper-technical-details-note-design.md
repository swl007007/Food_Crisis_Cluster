# Paper Technical Details Note Design

## Purpose

Add reviewer-response technical detail notes to `final_artifacts_in_paper_updated/`
without changing model code, rerunning results, or overstating methods that are
not implemented. The paper-facing appendix text must describe only behavior that
is present in the current repository. Reviewer requests that point to missing
sensitivity analyses or unimplemented controls must be captured separately as
internal patch candidates, not appended to the paper appendix.

## Scope

Create two Markdown artifacts:

1. `final_artifacts_in_paper_updated/technical_details_review_note.md`
   - Chinese review/audit section first.
   - English paper appendix text last.
   - Covers reviewer comments 4 through 13.
   - Uses code-faithful descriptions only.
2. `final_artifacts_in_paper_updated/technical_details_unimplemented_patch_note.md`
   - Internal Chinese note only.
   - Lists reviewer-requested items that are not currently implemented or not
     supported by existing artifacts.
   - Must not be presented as paper appendix text.

No existing paper tables, figures, metrics, model scripts, batch files, or
pipeline outputs are modified.

## Evidence Base

The notes will be grounded in the current implementation paths:

- Recursive partitioning and split acceptance:
  `src/partition/transformation.py`, `src/partition/partition_opt.py`,
  `src/tests/sig_test.py`, and `config.py`.
- Polygon-level metrics and local model evaluation:
  `scripts/compare_partitioned_vs_pooled_rf_k40_nc4.py`,
  `src/metrics/metrics.py`, and generated Stage 3 output contracts.
- Consensus matrix, spatial kernel, KNN sparsification, and spectral clustering:
  `scripts/step4_similarity_matrix.py`, `scripts/step5_sparsification.py`,
  `scripts/step6_complete_clustering_pipeline.py`, and
  `PIPELINE_WORKFLOW.md`.
- Local RF training and fallback behavior:
  `scripts/compare_partitioned_vs_pooled_rf_k40_nc4.py` and
  `src/model/model_RF.py`.

## Paper-Facing Claims Allowed

The English appendix may state the following current behavior:

- Stage 1 learns recursive binary spatial partitions on the 2018-2020
  partition-learning window and Stage 3 evaluates fixed partitions on
  2021-2024.
- Candidate binary splits are generated by a scan-statistic search over
  validation-set polygon/group summaries, with group balance controlled by
  `FLEX_RATIO=0.1` and `FLEX_TYPE='n_group'`.
- Crisis emphasis is implemented through class-1 selected scoring and class-1
  focused split acceptance, not through a custom RF loss function.
- Current split acceptance uses `MIN_DEPTH=1`, `MAX_DEPTH=6`,
  `MIN_BRANCH_SAMPLE_SIZE=0`, `MIN_SCAN_CLASS_SAMPLE=0`, and
  `MIN_CLASS_1_IMPROVEMENT_THRESHOLD=0.01`; borderline cases use the current
  class-1 focused significance fallback in `src/tests/sig_test.py`.
- Polygon-level Stage 3 summaries are computed from binary predictions grouped
  by `FEWSNET_admin_code`, including counts, class-1 precision, recall, F1, and
  binary error rates.
- Stage 2 plan weights are
  `max(logit(F1_partitioned) - logit(F1_base), 0)`.
- Spatial modulation uses a Gaussian kernel on haversine distance with
  `sigma_degrees=5.0`.
- KNN sparsification uses fixed `k=40`.
- Eigengap selection is based on the normalized graph Laplacian computed in
  `scripts/step5_sparsification.py`.
- Final clustering uses scikit-learn `SpectralClustering` with precomputed
  affinity, k-means label assignment, `random_state=42`, and nearest-neighbor
  geographic assignment for nodes outside the largest connected component.
- Stage 3 local RF models use `n_estimators=100`, `max_depth=None`,
  `random_state=5`, `n_jobs=1`; local models fall back to the pooled model when
  a partition has fewer than 50 training samples or only one observed class.
- SMOTE is attempted for eligible local partitions when `imbalanced-learn` is
  available; RF `class_weight` is currently `None`; standard predictions use
  hard class predictions rather than calibrated probabilities.

## Claims To Exclude From Appendix

The appendix must not claim that the current workflow already includes:

- k sensitivity analysis or ex-post tuning justification for `k=40`.
- Variance penalties or small-sample penalties in Stage 2 plan weights.
- Probability calibration, log-loss optimization, AUC optimization, or a custom
  weighted RF loss.
- A formal rule that trades precision losses against recall gains beyond the
  implemented class-1 score acceptance logic.
- Exhaustive contiguity-constrained split search.
- Formal distance-band sensitivity analysis for the Gaussian spatial kernel.
- Reported fallback frequency tables unless computed from existing artifacts
  during implementation.

These exclusions belong in
`technical_details_unimplemented_patch_note.md` as internal future-work patches.

## Verification

Implementation verification should check:

- Both new Markdown files exist in `final_artifacts_in_paper_updated/`.
- The review note ends with the English appendix section.
- The appendix section does not contain unimplemented claims listed above.
- File references in both notes point to existing repository paths.
- `git diff --check` passes for the added Markdown files.

## Out Of Scope

- No model retraining.
- No table or figure regeneration.
- No k-sensitivity experiment.
- No statistical test additions.
- No manuscript editing outside `final_artifacts_in_paper_updated/`.
