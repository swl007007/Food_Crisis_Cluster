# Quickstart: GeoDT Branch-Specific Local Tree Interpretability Diagnostic

This quickstart documents the implemented standalone exploratory diagnostic interface and validation flow.

## Preconditions

- Python 3.12+ project environment is active.
- A GeoDT monthly archive or synthetic GeoDT-like fixture is available.
- Existing GeoDT artifacts are treated as read-only.
- Generated outputs go to a diagnostics output directory and are ignored unless explicitly promoted.

## 1. Audit-only dry run

Use audit-only mode first to verify archive completeness and branch selection without rendering a figure:

```bash
python scripts/plot_geodt_branch_tree_comparison.py \
  --audit-only \
  --archive-path result_GeoDT_2024_fs1_2024-10_visual \
  --output-dir result_GeoDT_2024_fs1_2024-10_visual/diagnostics/output \
  --k 3 \
  --max-plot-depth 3
```

Expected behavior:
- bounded archive/preflight scan;
- branch assignment source selected or rejected with reasons;
- feature-name source selected or rejected with reasons;
- branch checkpoints classified;
- eligible/ineligible branches listed;
- pairwise Jaccard scores computed;
- selected readable pair recorded;
- no PNG/PDF figure rendered.

## 2. Figure generation

After audit-only mode succeeds:

```bash
python scripts/plot_geodt_branch_tree_comparison.py \
  --archive-path result_GeoDT_2024_fs1_2024-10_visual \
  --output-dir result_GeoDT_2024_fs1_2024-10_visual/diagnostics/output \
  --k 3 \
  --max-plot-depth 3
```

Expected outputs:
- `geodt_branch_tree_compare_<YYYY-MM>_<fs>_<branchA>_vs_<branchB>.png`
- `geodt_branch_tree_compare_<YYYY-MM>_<fs>_<branchA>_vs_<branchB>.pdf` when feasible
- `geodt_branch_tree_compare_<YYYY-MM>_<fs>_<branchA>_vs_<branchB>_metadata.json`
- audit summary if configured or generated by default

## 3. Visual archive plus source artifact-provider folder

If the visual archive lacks `checkpoints/` or `space_partitions/`, provide a matching source run folder:

```bash
python scripts/plot_geodt_branch_tree_comparison.py \
  --archive-path result_GeoDT_2024_fs1_2024-10_visual \
  --artifact-provider-path result_GeoDT_2024_fs1_2024-10 \
  --audit-only \
  --k 3 \
  --max-plot-depth 3
```

The diagnostic must record both paths and compatibility evidence.

## 4. Discovery root fallback

To let the diagnostic choose the best available archive within a bounded root:

```bash
python scripts/plot_geodt_branch_tree_comparison.py \
  --archive-root . \
  --audit-only \
  --k 3 \
  --max-plot-depth 3
```

The implementation must search only within the configured root and must not scan arbitrary user directories or the entire filesystem.

## 5. Reproduction mode

To reproduce a prior selection from metadata:

```bash
python scripts/plot_geodt_branch_tree_comparison.py \
  --reproduce-from result_GeoDT_2024_fs1_2024-10_visual/diagnostics/output/geodt_branch_tree_compare_2024-10_fs1_0_vs_1_metadata.json \
  --output-dir result_GeoDT_2024_fs1_2024-10_visual/diagnostics/reproduction
```

Expected behavior:
- recover selected archive, branch IDs, checkpoint paths, feature-name source, K, top-K features, and score;
- write a reproduction report containing `reselected_pair == false`;
- do not reselect another branch pair;
- fail with a structured reproduction failure summary if recorded artifacts are missing or changed;
- do not render PNG/PDF outputs in the implemented reproduction report path;
- bitwise-identical image output is not required.

## 6. Safety checks

Before accepting output:
- confirm plotted trees came from branch-specific checkpoints;
- confirm root/global `dt_rules_*.csv` were not used as rule source;
- confirm no existing checkpoints, partition artifacts, `dt_rules`, deliverables, or evaluation outputs were modified;
- confirm metadata includes archive discovery and evidence validation status.
